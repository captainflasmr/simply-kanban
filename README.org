#+author: James Dyer
#+email: captainflasmr@gmail.com
#+language: en
#+options: ':t toc:nil author:nil email:nil num:nil title:nil
#+startup: showall

A lightweight kanban board for Org files.  The board is a live view of the current Org buffer — there is *no separate database*, the Org file is the single source of truth.

- *Columns* are the buffer's Org TODO keywords (the =#+TODO:= workflow, e.g.  =TODO NEXT DOING | DONE=).
- *Cards* are the headings carrying those keywords.
- *Moving a card* between columns changes the heading's TODO state via =org-todo=, written straight back to the Org buffer.

The rendering and navigation are modelled on the kanban view in [[https://github.com/captainflasmr/simply-annotate][simply-annotate]].

* Status

Works against the current Org buffer, a multi-board Org file, or all agenda files.  Strictly keyboard-driven.  Future ideas: WIP limits, scheduled/deadline badges, swimlanes by tag.

* Install

Clone and load:

#+begin_src elisp
(add-to-list 'load-path "/path/to/simply-kanban")
(require 'simply-kanban)
#+end_src

The only dependency is =transient= (used for the =SPC= menu), which is bundled with Emacs 28.1+; on Emacs 27.2 install it from GNU ELPA.

* Usage

Open an Org file with TODO headings and run =M-x simply-kanban= for a board of the current buffer, or =M-x simply-kanban-agenda= for a board aggregating all your =org-agenda-files=.

In an aggregated board the columns are the *union* of the agenda files' TODO keywords, and each card shows which file it comes from (=» file.org=).  Moving a card follows that card's *own* file workflow and is written back to that file, so files using different keyword sequences coexist safely.

A header-line shows the source and the key reminders.  Columns expand to fill the board window; after resizing the window press =g= to refit them.

| Key       | Action                                               |
|-----------+------------------------------------------------------|
| =n= / =p= | move down / up the cards in a column                 |
| =f= / =b= | move across columns (also =TAB= / =S-TAB=), wrapping |
| =}= / ={= | advance / retreat card a stage                       |
| =s=       | set status (choose any stage)                        |
| =RET=     | reveal the heading (focus stays on the board)        |
| =v=       | jump to the heading in another window                |
| =k=       | delete the heading (with confirmation)               |
| =t=       | filter board by tag                                  |
| =T=       | clear tag filter                                     |
| =S=       | filter board by sprint (=SPRINT= property)           |
| =:=       | set the Org tags on the card at point                |
| =,=       | set the Org priority of the card at point            |
| =;=       | set the Org effort estimate on the card at point     |
| =#=       | set the sprint (=SPRINT= property) on the card        |
| =e= / =E= | toggle the body of the card / every card             |
| =F=       | toggle follow mode (show heading as you move)        |
| =B=       | switch board (multi-board files only)                |
| =g=       | refresh                                              |
| =SPC= / =?= | open the transient menu                            |
| =q=       | quit                                                 |

Press =SPC= (or =?=) for a =transient= menu grouping every command (Navigate / Move-Edit / Reveal / Board), modelled on the menu in [[https://github.com/captainflasmr/simply-annotate][simply-annotate]].

The card at point is highlighted, and navigating moves the highlight onto the new card.

Cards are deliberately compact so you can fit many per window: a card shows its title (prefixed by a priority cookie such as =[#A]= only when one is set), its tags when present, and its Org effort estimate as =Effort: 2:00= when the heading carries an =Effort= property.  In an aggregated board it also shows its source file (=» file=).  Press =;= to set the effort with Org's native prompt (=org-set-effort=); each column header then sums its cards' efforts in brackets (=[2:00]=), giving a Jira-style per-stage workload total.  Press =e= to expand a card and show the heading's body text inline.  When you reveal a heading with =RET= (or while follow mode is on) the target heading line briefly pulses, and focus stays on the board.

* Multiple boards in one file

A single Org file can hold several boards.  Make each board a *level-1 heading with no TODO keyword* and put its cards as TODO headings inside that subtree:

#+begin_src org
,* Project Alpha
,** TODO design
,** DOING build
,* Project Beta
,** TODO research
,** DONE prototype
#+end_src

=M-x simply-kanban= then prompts for which board to open, and =B= switches between them.  Any *loose* level-1 TODO headings sitting at the top of the file (outside a board heading) are still offered as a flat board named by =simply-kanban-toplevel-name= ("Top Level" by default).  A plain file whose top-level headings are themselves TODO items continues to open as a single flat board, exactly as before.

When a file holds more than one board the chooser (and =B=) also offers an *All Boards* entry that aggregates every board into one view — the file's TODO keywords become the columns and each card denotes its board (=▸ Project Alpha=), in the same spirit as the source-file marker (=» file=) on an aggregated agenda board.  Moving a card still changes only its TODO state, so it stays in its own board.  This entry is controlled by =simply-kanban-all-boards= (default =t=) and named by =simply-kanban-all-boards-name=.

Status changes and deletions are written straight back to the source file and, by default, saved (see =simply-kanban-save-after-change=).

* Sprints

Sprints are a plain Org property, not a date range: tag a heading with a =SPRINT= property holding an integer, and the board can filter to that sprint.  There is no calendar arithmetic — a card is "in" sprint 3 purely because it carries =:SPRINT: 3=, so you can assign any heading to any sprint freely.

#+begin_src org
,* TODO Design the parser
,:PROPERTIES:
,:SPRINT: 3
,:END:
#+end_src

- Press =#= on a card to set (or, with empty input, remove) its =SPRINT=, using a simple number prompt — written straight back to the Org heading.
- Press =S= to display only one sprint; the prompt offers the sprint numbers present on the board and accepts any integer, and empty input clears the filter to show every sprint again.  The active sprint shows in the header-line as =[sprint: N]=.
- When *no* sprint filter is active each card shows its own =Sprint: N= badge so you can see the spread; once you filter to a single sprint that badge is hidden (every visible card shares it).

The =SPRINT= property is read with inheritance, so setting =:SPRINT:= on a board container (or any parent heading) applies to all the TODO headings beneath it unless a child overrides it — handy for assigning a whole board to a sprint at once.

Set the sprint shown by default with =simply-kanban-default-sprint= (default =nil=, meaning show all sprints).  When it is an integer, every freshly opened board starts filtered to that sprint; you can still change the displayed sprint live with =S=.  For example, to make sprint 2 the default view:

#+begin_src elisp
(setq simply-kanban-default-sprint 2)
#+end_src

* Customisation

- =simply-kanban-min-column-width= (default 24) — columns expand to fill the window but never go narrower than this.
- =simply-kanban-column-gap= (default 2) — spaces between columns.
- =simply-kanban-buffer-name= — name of the board buffer.
- =simply-kanban-auto-refresh= (default =t=) — refresh the board automatically whenever its source Org buffer is saved.
- =simply-kanban-sort-by-priority= (default =nil=) — when non-nil, sort cards within each column by priority (A > B > C > none).
- =simply-kanban-show-effort= (default =t=) — show each card's Org =Effort= estimate (=Effort: 2:00=) and sum each column's efforts in brackets (=[2:00]=) in its header.
- =simply-kanban-default-sprint= (default =nil=) — sprint number a board filters to when first opened; =nil= shows all sprints.  Change the displayed sprint live with =S=.
- =simply-kanban-show-sprint= (default =t=) — show a card's =SPRINT= number (=Sprint: N=) while no sprint filter is active.
- =simply-kanban-save-after-change= (default =t=) — save the source Org buffer after a status change or deletion.
- =simply-kanban-pulse-on-goto= (default =t=) — briefly pulse the target heading line when revealing it (=RET= and follow mode).
- =simply-kanban-toplevel-name= (default ="Top Level"=) — name of the flat board holding a multi-board file's loose level-1 TODO headings.
- =simply-kanban-all-boards= (default =t=) — in a multi-board file, offer an aggregate board (in the chooser and =B=) showing every board's cards at once, each card denoting its board.
- =simply-kanban-all-boards-name= (default ="All Boards"=) — name of that aggregate entry.

Faces: =simply-kanban-current-card= (focused card), =simply-kanban-tag= (card tags), =simply-kanban-effort= (effort badge and column total), =simply-kanban-sprint= (sprint badge), =simply-kanban-flash= (heading pulse), =simply-kanban-column-header=.

Simply Kanban's niche is the *live, keyboard-driven board buffer*: =org-kanban= and =kanban.el= render a static table back into the Org file (you still edit TODO states by hand or by shifting a link), while =org-trello= trades the offline, single-source model for two-way sync with a remote Trello account.  Simply Kanban keeps the Org buffer as the only source of truth and gives you a navigable board on top of it.

* Feature Gaps & Roadmap

Where Simply Kanban already leads is the live, keyboard-driven board buffer; what follows is the *inverse* view — capabilities the other Emacs kanban tools offer that Simply Kanban currently does *not*.  Each row is a candidate enhancement.  To the best of my knowledge — things move, so treat this as a starting point rather than gospel.

| Missing / partial feature             | [[https://github.com/gizmomogwai/org-kanban][org-kanban]] | [[https://hg.sr.ht/~arnebab/kanban][kanban.el]] | [[https://github.com/org-trello/org-trello][org-trello]] | simply-kanban |
|---------------------------------------+------------+-----------+------------+---------------|
| In-file table (exports with document) | Yes        | Yes       | No         | No            |
| Clickable heading links in board      | Yes        | No        | No         | Partial       |
| Arbitrary match/query filter          | Yes        | No        | No         | Partial       |
| Heading-depth / property scoping      | Yes        | No        | No         | No            |
| Add / create a card from the board    | No         | No        | Yes        | No            |
| Edit card title/body from the board   | No         | No        | Yes        | No            |
| Deadline / scheduled badges           | No         | No        | Yes        | No            |
| Checklist / subtask progress          | No         | No        | Yes        | No            |
| Labels / colour coding                | No         | No        | Yes        | No            |
| Assignees / members                   | No         | No        | Yes        | No            |
| Comments on cards                     | No         | No        | Yes        | No            |
| Card count per column                 | No         | No        | Yes        | No            |
| WIP limits per column                 | No         | No        | Partial    | No            |
| Swimlanes (group rows by tag)         | No         | No        | No         | No            |
| Mouse drag-and-drop                   | No         | No        | No         | No            |
| Remote / cloud sync                   | No         | No        | Yes        | No            |
| MELPA availability                    | Yes        | Yes       | Yes        | No            |

Reading the gaps as a rough roadmap, three themes emerge:

- *Richer cards* — deadline/scheduled badges, checklist progress, label colours and per-column WIP limits are all derivable from data already in the Org subtree (=DEADLINE=, =SCHEDULED=, checkbox stats, tags), so they need no new storage — only rendering.  These are the cheapest wins and several (=WIP limits=, =deadline badges=, =swimlanes by tag=) already appear under *Status → Future ideas*.  The =Effort= property is already surfaced this way: an =Effort:= badge per card and a bracketed total per column.
- *Editing from the board* — add-card, rename, and inline body editing would close the gap with =org-trello='s card creation while keeping the Org buffer as the single source of truth.
- *Broader selection* — =org-kanban='s =:match= query and depth scoping point at a more flexible card-selection model than the current TODO-keyword + single-tag filter (which is why those two rows are marked =Partial=).

Deliberately *out of scope*: remote/cloud sync, assignees and comments are =org-trello='s domain via the Trello service and run counter to Simply Kanban's offline, single-file model — listed for completeness, not as planned work.

* Development

There is an ERT suite and a =Makefile=:

#+begin_src bash
make test       # run the ERT suite
make compile    # byte-compile, treating warnings as errors
make checkdoc   # run checkdoc
make lint       # run package-lint (after `make deps')
make deps       # install package-lint into ./.elpa
make all        # compile + test + checkdoc
#+end_src

A GitHub Actions workflow (=.github/workflows/ci.yml=) runs these across Emacs 27.2–30.1 and snapshot on every push and pull request.
