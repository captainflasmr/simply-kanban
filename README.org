#+title: Simply Kanban: An Org-linked Kanban Board
#+author: James Dyer
#+email: captainflasmr@gmail.com
#+language: en
#+options: ':t toc:nil author:nil email:nil num:nil title:nil
#+startup: showall

A lightweight kanban board for Org files.  The board is a live view of the current Org buffer — there is *no separate database*, the Org file is the single source of truth.

- *Columns* are the buffer's Org TODO keywords (the =#+TODO:= workflow, e.g.  =TODO NEXT DOING | DONE=).
- *Cards* are the headings carrying those keywords.
- *Moving a card* between columns changes the heading's TODO state via =org-todo=, written straight back to the Org buffer.

The rendering and navigation are modelled on the kanban view in [[https://github.com/captainflasmr/simply-annotate][simply-annotate]].

* Status

Works against the current Org buffer, a multi-board Org file, or all agenda files.  Strictly keyboard-driven.  Future ideas: WIP limits, scheduled/deadline badges, swimlanes by tag.

* Install

Clone and load:

#+begin_src elisp
(add-to-list 'load-path "/path/to/simply-kanban")
(require 'simply-kanban)
#+end_src

The only dependency is =transient= (used for the =SPC= menu), which is bundled with Emacs 28.1+; on Emacs 27.2 install it from GNU ELPA.

Or with =use-package=, binding the two entry points to global keys:

#+begin_src elisp
(use-package simply-kanban
  :demand t
  :load-path "~/.emacs.d/offline-packages/local-packages/simply-kanban"
  :bind
  ("C-c K" . simply-kanban)
  ("C-c A" . simply-kanban-agenda))
#+end_src

* Usage

Open an Org file with TODO headings and run =M-x simply-kanban= for a board of the current buffer, or =M-x simply-kanban-agenda= for a board aggregating all your =org-agenda-files=.

In an aggregated board the columns are the *union* of the agenda files' TODO keywords, and each card shows which file it comes from (=» file.org=).  Moving a card follows that card's *own* file workflow and is written back to that file, so files using different keyword sequences coexist safely.

The board buffer's name identifies its source, the active sprint filter appears in the mode line, and the header line shows the remaining status indicators and key reminders.  Columns expand to fill the board window; after resizing the window press =g= to refit them.

| Key       | Action                                               |
|-----------+------------------------------------------------------|
| =n= / =p= | move down / up the cards in a column                 |
| =f= / =b= | move across columns (also =TAB= / =S-TAB=), wrapping |
| =}= / ={= | advance / retreat card a stage                       |
| =s=       | set status (choose any stage)                        |
| =RET=     | reveal the heading (focus stays on the board)        |
| =C-u RET= / =C-u C-m= | jump to the heading in the Org file     |
| =k=       | delete the heading (with confirmation)               |
| =t=       | filter board by tag                                  |
| =T=       | clear tag filter                                     |
| =S=       | filter board by sprint (=SPRINT= property)           |
| =C=       | clear sprint filter                                  |
| =:=       | set the Org tags on the card at point                |
| =,=       | set the Org priority of the card at point            |
| =;=       | set the Org effort estimate on the card at point     |
| =P=       | set the story points on the card at point            |
| =i=       | clock in the card at point                           |
| =o=       | clock out the running clock                          |
| =#=       | set the sprint (=SPRINT= property) on the card        |
| =e= / =E= | toggle the body of the card / every card             |
| =N=       | add a timestamped note to the card at point           |
| =L=       | toggle the card's LOGBOOK drawer on the board         |
| =c=       | toggle compact single-line card metadata             |
| =v=       | show/hide STORY cards                                |
| =l=       | set the max card-title length (empty = no limit)     |
| =F=       | toggle follow mode (show heading as you move)        |
| =B=       | switch board (multi-board files only)                |
| =g=       | refresh                                              |
| =SPC= / =?= | open the transient menu                            |
| =q=       | quit                                                 |

Press =SPC= (or =?=) for a =transient= menu grouping the commands (Move-Edit / Clock / Reveal / Board), modelled on the menu in [[https://github.com/captainflasmr/simply-annotate][simply-annotate]].

The card at point is highlighted, and navigating moves the highlight onto the new card.  Use =C-u RET= (or =C-u C-m=) to jump to the heading and move focus to the Org file instead of keeping it on the board.

To go the other way -- from a heading in the Org file to its card -- run =M-x simply-kanban-show-card= (bound to =C-c ;= in Org buffers) from the Org buffer.  It is the inverse of =RET=: it finds the heading at (or enclosing) point among the board's cards and selects that card, showing the board in another window while focus stays in the Org buffer.  The matched card is filled (face =simply-kanban-mark=) so you can see at a glance which card relates to the heading; that fill clears the moment you navigate to another card on the board.  If no board is open yet it creates one for the file first -- in a split to the right, so the original file stays visible on the left -- and the command always tries to take you to a card.  To jump straight to the card instead, leaving focus on the board, use =C-u C-c ;= or =M-x simply-kanban-jump-to-card=.

To rebind it, e.g.:

#+begin_src emacs-lisp
(with-eval-after-load 'org
  (define-key org-mode-map (kbd "C-c k") #'simply-kanban-show-card))
#+end_src

Cards are deliberately compact: by default a card shows its title (prefixed by a priority cookie such as =[#A]= only when one is set), a type/hierarchy line when the card is a story or has a parent task relationship, one metadata line, and a progress bar when it has progress data.  The metadata line lists the board and source-file markers when present, then effort, remaining or over-budget time, sprint, and tags, omitting values the card lacks; numeric values carry no labels and the sprint value has no =Sprint:= prefix (see [[*Card layout]]).  Press =;= to set the effort with Org's native prompt (=org-set-effort=); each column header then sums its cards' efforts in brackets (=[2:00]=), giving a Jira-style per-stage workload total.  Story points live in the =STORY_POINTS= property: press =P= to set them, the detailed layout shows them as =Points: 5=, and each column header sums its cards' points in parentheses (=(8 pts)=).  In the detailed layout, cards with clock entries show their clocked time; a running clock adds =(run)=.  Once a card has clocked time it also shows the remaining time, calculated as Effort minus clocked time (floored at zero); a card whose clocked time exceeds its estimate instead shows over-budget time prefixed with =+= in the warning face.  Press =i= to clock in the card at point and =o= to clock out the running clock.  Press =c= to switch to the detailed layout, where each value gets its own labelled line (=Effort: 2:00=, =Points: 5=, =Clocked: 1:30=, and =Remaining: 1d 3h 42m= or =Over: 30m=).  Set =simply-kanban-show-clock-total= to add each column's clocked total in braces (={1:30}=) after the effort total, =simply-kanban-show-remaining-total= to add its remaining total in angle brackets (=<1d 3h 42m>=), and =simply-kanban-show-over-total= to add its over-budget total after an exclamation mark (=!30m=).  Press =e= to expand a card and show the heading's body text inline.  When you reveal a heading with =RET= (or while follow mode is on) the target heading line briefly pulses, and focus stays on the board.

* Multiple boards in one file

A single Org file can hold several boards.  Make each board a *level-1 heading with no TODO keyword* and put its cards as TODO headings inside that subtree:

#+begin_src org
,* Project Alpha
,** TODO design
,** DOING build
,* Project Beta
,** TODO research
,** DONE prototype
#+end_src

=M-x simply-kanban= then prompts for which board to open, and =B= switches between them.  Each board opens in its own buffer named after its source and board (for example, =*Simply Kanban: projects.org ▸ Project Alpha*=), so several boards can stay open at once; reopening a board reuses its buffer, and =B= selects an already-open board instead of duplicating it.  Any *loose* level-1 TODO headings sitting at the top of the file (outside a board heading) are still offered as a flat board named by =simply-kanban-toplevel-name= ("Top Level" by default).  A plain file whose top-level headings are themselves TODO items continues to open as a single flat board, exactly as before.

When a file holds more than one board the chooser (and =B=) also offers an *All Boards* entry that aggregates every board into one view — the file's TODO keywords become the columns and each card denotes its board (=▸ Project Alpha=), in the same spirit as the source-file marker (=» file=) on an aggregated agenda board.  Moving a card still changes only its TODO state, so it stays in its own board.  This entry is controlled by =simply-kanban-all-boards= (default =t=) and named by =simply-kanban-all-boards-name=.

Status changes and deletions are written straight back to the source file and, by default, saved (see =simply-kanban-save-after-change=).

* Sprints

Sprints are a plain Org property, not a date range: tag a heading with a =SPRINT= property holding any text, and the board can filter to that sprint.  There is no calendar arithmetic — a card is "in" a sprint purely because it carries that =SPRINT= value, so numbers such as =:SPRINT: 3=, names such as =:SPRINT: Backlog=, and dates such as =:SPRINT: 2026-Q4= all work equally well.

#+begin_src org
,* TODO Design the parser
,:PROPERTIES:
,:SPRINT: 2026-Q4
,:END:
#+end_src

- Press =#= on a card to set (or, with empty input, remove) its =SPRINT=, using a free-text prompt — written straight back to the Org heading.
- Press =S= to display only one sprint; the prompt offers the sprint values present on the board and accepts any text, and empty input clears the filter to show every sprint again.  The active sprint shows in the mode line as =[sprint: TEXT]=.
- When *no* sprint filter is active each card shows its own =Sprint: TEXT= badge so you can see the spread; once you filter to a single sprint that badge is hidden (every visible card shares it).

The =SPRINT= property is read with inheritance, so setting =:SPRINT:= on a board container (or any parent heading) applies to all the TODO headings beneath it unless a child overrides it — handy for assigning a whole board to a sprint at once.

If you prefer to define sprints by section headings instead of properties, set =simply-kanban-sprint-from-heading= to =t=.  Then, when a card has no =SPRINT= property, the nearest ancestor heading without a TODO keyword supplies its sprint:

#+begin_src org
,* Sprint 1
,** TODO Write the parser
,* Sprint 2
,** TODO Write the tests
#+end_src

This lets a single file be split into sprints by its headings.  The nearest ancestor wins: a =SPRINT= property on a heading takes precedence over that heading's text, and a =SPRINT= property on the card itself always takes precedence, so you can still override individual cards or whole sections.

Set the sprint shown by default with =simply-kanban-default-sprint= (default =nil=, meaning show all sprints).  When it is a string, every freshly opened board starts filtered to that sprint; you can still change the displayed sprint live with =S=.  For example, to make sprint 2 the default view:

#+begin_src elisp
(setq simply-kanban-default-sprint "2")
#+end_src

* Sprint summary

The package provides a dynamic block that summarises all cards by sprint:

#+begin_src org
,#+BEGIN: simply-kanban-sprint-summary :scope file
,#+END:
#+end_src

Each row reports the sprint, task count, done count, story points, effort-weighted progress, estimate, actual clocked time, and remaining estimate.  Durations use the Jira-style day/hour/minute format and the source buffer's =org-duration-units=.  Recompute the block with =C-c C-c=, or update it alongside other dynamic blocks with =M-x org-update-all-dblocks=.  The default scope is the whole file; use =:scope subtree= to limit it to the current subtree.

* Clocking

The board reads the source headings' Org clock entries, so time clocked anywhere in Org is visible on the cards.  Press =i= to clock in the card at point and =o= to clock out whichever task is running.  The active clock is shown in the header line, a solid block outline is drawn around the entire card in the ticket's colour, and the detailed layout displays =Clocked: 1:30 (run)=.  Started cards also show the time left, =Remaining: 1d 3h 42m=, calculated from the Effort estimate minus clocked time; a =DONE= card has zero remaining, and a card whose clocked time exceeds its estimate shows =Over: 30m= instead.  The day length in that format follows =org-duration-units= from the source Org buffer, so the project's 37-hour week renders one day as =7h24m= even when the board buffer itself is not visiting that file.

- =simply-kanban-show-clock= (default =t=) — show each card's clocked time and the active clock marker in the detailed layout; compact cards omit clocked time.
- =simply-kanban-show-clock-total= (default =nil=) — append each column's summed clocked time in braces (={1:30}=) after its effort total.
- =simply-kanban-show-remaining= (default =t=) — show remaining time on started cards.
- =simply-kanban-show-remaining-total= (default =nil=) — append each column's summed remaining time in angle brackets (=<1d 3h 42m>=) after its effort total.
- =simply-kanban-show-over-total= (default =nil=) — append each column's summed over-budget time after an exclamation mark (=!30m=).
- Press =g= to refresh the displayed clock times; the board updates again after a status change, clock in/out, or source save.

Clock commands save the source buffer when =simply-kanban-save-after-change= is non-nil, matching the other card edits.

* Notes and logbook

Press =N= on a card to add a timestamped note with Org's native note prompt (=org-add-note=); finish with =C-c C-c=. The board stays visible while the note is written: the source Org buffer and the =*Org Note*= buffer open in side windows, and the board returns to the same card after storing or cancelling. The note is stored on the card's heading, honouring =org-log-into-drawer=, and boards built from that Org buffer refresh once the note is stored. Press =L= to toggle the card's =LOGBOOK= drawer on the board, showing its clock entries and any notes stored in the drawer below a =Logbook= divider. The body shown by =e= includes notes and prose but omits =LOGBOOK= clock entries; notes stored outside the drawer remain part of that body.

* Card layout

By default cards use a compact layout: the title is followed by one metadata line and then the progress bar.  The metadata line lists the board and source-file markers when present, then effort, remaining or over-budget time, sprint, and tags, skipping absent values.  Values are separated by spaces, numeric values are unlabelled, durations use colon-separated units (so =1d:1h:23m= is one day, one hour and 23 minutes), and the sprint value appears without a =Sprint:= prefix.  For example, =4:00 1h= reads as effort and remaining; the faces distinguish them.  Story points and clocked time are omitted from this line and appear only in the detailed layout.  A running clock adds =(run)= in the detailed layout, and over-budget time is prefixed with =+=.  The line is truncated with an ellipsis when the column is too narrow.  Press =c= (=simply-kanban-toggle-compact=) to toggle the current board between the compact and detailed layouts.  The detailed layout puts each value on its own labelled line, as in =Effort: 2:00= or =Remaining: 1d 3h 42m=.

- =simply-kanban-compact-cards= (default =t=) — start boards in the compact single-line metadata layout; set it to =nil= to start in the detailed layout.

* Stories and tasks

Ticket types are inferred from the Org hierarchy.  A TODO heading with TODO descendants is a =STORY=; leaf TODO headings are =TASK=s.  A childless heading can also be marked as a story by giving it a =TICKET_TYPE= property of =STORY=.  Ticket headings should start with a Jira number such as =MM-1472=; the board parses that key for the card and uses the parent's key in compact hierarchy labels.

#+begin_example
** TODO MM-1472 Scenario Specification
:PROPERTIES:
:TICKET_TYPE: STORY
:END:
*** TODO MM-1478 Agree MIMESIS namespace
*** DOING MM-1479 Validate the example
#+end_example

A story is an ordinary TODO heading, so it has its own status, can be clocked, and moves independently of its child headings.  Only TODO headings become cards, so give a story a TODO keyword (as in the example) when you want it on the board.  A non-TODO heading marked =TICKET_TYPE: STORY= still names the parent on its child cards, but is not itself a card; an unmarked grouping heading is just a container.  Story cards use a double-line outline in the =simply-kanban-story= face, while tasks use the normal single-line box.  Story cards are hidden by default; press =v= (=simply-kanban-toggle-stories=) or set =simply-kanban-show-stories= to show them.  Task cards keep their parent labels while stories are hidden, and the header line shows =[stories]= when stories are visible.  Jira numbers are shown in bold in card titles and hierarchy labels.  Cards carry a type/hierarchy line: compact cards use a short form (=STORY 3 children=, =TASK parent MM-1472=), while the detailed layout spells out =child of MM-1472 Scenario Specification= and =parent of 3 children (1 done)=.  Expanding a story with =e= lists all its children under a =Children= divider, each with its TODO state, Jira key, and title.  Story cards also show the story's aggregated clocked time from Org's clock summary.

- =simply-kanban-show-ticket-types= (default =t=) — show the type and hierarchy line on cards; set it to =nil= to hide it.
- =simply-kanban-show-stories= (default =nil=) — show STORY cards on boards; when nil only TASK cards appear, though tasks still name their parent story.
- =simply-kanban-jira-number-regexp= — regexp matching the Jira key at the start of a ticket title; the default accepts an uppercase prefix and digits, such as =MM-1472=.

* Column progress

The divider under each column header is a progress bar.  Filled blocks show the completed share of that column's estimated effort: a =DONE= card counts as fully complete, while an in-progress card counts its clocked time capped at its estimate.  The empty portion is drawn in the =shadow= face, and the filled portion uses the column's TODO-keyword colour.  When no effort estimates are set, the done-card count is used instead.

- =simply-kanban-show-column-progress= (default =t=) — replace the column divider with the progress bar; set it to =nil= to restore the plain dashes.

* Card progress

Each card with progress data also carries its own bar, drawn with the same filled (=█=) and empty (=░=) blocks as the column divider.  A =DONE= card is fully filled, while any other card is filled by its clocked time against its =Effort= estimate, capped at fully complete.  Cards without an effort estimate, or with an estimate but no clocked time, show no bar unless they are =DONE=, so an untouched card never displays an empty bar.  The filled portion uses the card's TODO-keyword colour and the empty portion uses the =shadow= face.

- =simply-kanban-show-card-progress= (default =t=) — show the per-card progress bar; set it to =nil= to hide it.

* Customisation

- =simply-kanban-min-column-width= (default 24) — columns expand to fill the window but never go narrower than this.
- =simply-kanban-column-gap= (default 2) — spaces between columns.
- =simply-kanban-max-title-length= (default =nil=) — when an integer, truncate card titles longer than this with an ellipsis; =nil= shows them in full.  Expanding a card (=e=) restores its full title alongside the body, and =l= adjusts the limit live for the current board.
- =simply-kanban-compact-cards= (default =t=) — condense each card's metadata onto a single line (see [[*Card layout]]); set it to =nil= to start new boards in the detailed layout, or press =c= to toggle a board.
- =simply-kanban-buffer-name= — base name for board buffers; each board appends its source and board name, so multiple boards get distinct buffers.
- =simply-kanban-auto-refresh= (default =t=) — refresh the board automatically whenever its source Org buffer is saved.
- =simply-kanban-sort-by-priority= (default =nil=) — when non-nil, sort cards within each column by priority (A > B > C > none).
- =simply-kanban-show-effort= (default =t=) — show each card's Org =Effort= estimate (=Effort: 2:00=) and sum each column's efforts in brackets (=[2:00]=) in its header.
- =simply-kanban-show-story-points= (default =t=) — show each card's =STORY_POINTS= as =Points: 5= in the detailed layout and sum each column's points in parentheses (=(8 pts)=) in its header; compact cards omit the value.
- =simply-kanban-show-clock= (default =t=) — show each card's clocked time (=Clocked: 1:30=) in the detailed layout and mark a running clock with =(run)=; compact cards omit the clocked value.
- =simply-kanban-show-clock-total= (default =nil=) — append each column's summed clocked time in braces (={1:30}=) after its effort total.
- =simply-kanban-show-remaining= (default =t=) — show =Remaining: 1d 3h 42m= on cards that have clocked time.
- =simply-kanban-show-remaining-total= (default =nil=) — append each column's summed remaining time in angle brackets (=<1d 3h 42m>=) after its effort total.
- =simply-kanban-show-over-total= (default =nil=) — append each column's summed over-budget time after an exclamation mark (=!30m=).
- =simply-kanban-show-column-progress= (default =t=) — replace each column divider with a progress bar showing the completed share of its estimated effort.
- =simply-kanban-show-card-progress= (default =t=) — show a progress bar inside each card, filled by its clocked time against its =Effort= estimate (=DONE= cards are fully filled).
- =simply-kanban-show-ticket-types= (default =t=) — show each card's STORY/TASK type and its parent story or child count.
- =simply-kanban-show-stories= (default =nil=) — show STORY cards on boards; when nil only TASK cards appear, though tasks still name their parent story.  Toggle the current board with =v=.
- =simply-kanban-jira-number-regexp= — regexp matching a Jira key at the start of a title; the default accepts keys such as =MM-1472=.
- =simply-kanban-default-sprint= (default =nil=) — sprint text a board filters to when first opened; =nil= shows all sprints.  Change the displayed sprint live with =S=.
- =simply-kanban-sprint-from-heading= (default =nil=) — when non-nil, derive a card's sprint from its nearest ancestor heading without a TODO keyword instead of requiring a =SPRINT= property.
- =simply-kanban-show-sprint= (default =t=) — show a card's sprint (=Sprint: TEXT=) while no sprint filter is active.
- =simply-kanban-save-after-change= (default =t=) — save the source Org buffer after a status change or deletion.
- =simply-kanban-pulse-on-goto= (default =t=) — briefly pulse the target heading line when revealing it (=RET= and follow mode).
- =simply-kanban-toplevel-name= (default ="Top Level"=) — name of the flat board holding a multi-board file's loose level-1 TODO headings.
- =simply-kanban-all-boards= (default =t=) — in a multi-board file, offer an aggregate board (in the chooser and =B=) showing every board's cards at once, each card denoting its board.
- =simply-kanban-all-boards-name= (default ="All Boards"=) — name of that aggregate entry.

Faces: =simply-kanban-current-card= (focused card), =simply-kanban-story= (STORY labels and double-line outlines), =simply-kanban-task= (TASK ticket label), =simply-kanban-jira= (bold Jira issue numbers), =simply-kanban-tag= (card tags), =simply-kanban-effort= (effort badge and column total), =simply-kanban-points= (story-points badge and column total), =simply-kanban-clock= (clocked-time badge), =simply-kanban-remaining= (remaining-time badge), =simply-kanban-over= (over-budget badge), =simply-kanban-sprint= (sprint badge), =simply-kanban-flash= (heading pulse), =simply-kanban-column-header=.

Simply Kanban's niche is the *live, keyboard-driven board buffer*: =org-kanban= and =kanban.el= render a static table back into the Org file (you still edit TODO states by hand or by shifting a link), while =org-trello= trades the offline, single-source model for two-way sync with a remote Trello account.  Simply Kanban keeps the Org buffer as the only source of truth and gives you a navigable board on top of it.

Where Simply Kanban already leads is the live, keyboard-driven board buffer; what follows is the *inverse* view — capabilities the other Emacs kanban tools offer that Simply Kanban currently does *not*. Reading the gaps as a rough roadmap, three themes emerge:

- *Richer cards* — deadline/scheduled badges, checklist progress, label colours and per-column WIP limits are all derivable from data already in the Org subtree (=DEADLINE=, =SCHEDULED=, checkbox stats, tags), so they need no new storage — only rendering.  These are the cheapest wins and several (=WIP limits=, =deadline badges=, =swimlanes by tag=) already appear under *Status → Future ideas*.  The =Effort= property is already surfaced this way: an =Effort:= badge per card and a bracketed total per column.
- *Editing from the board* — add-card, rename, and inline body editing would close the gap with =org-trello='s card creation while keeping the Org buffer as the single source of truth.
- *Broader selection* — =org-kanban='s =:match= query and depth scoping point at a more flexible card-selection model than the current TODO-keyword + single-tag filter (which is why those two rows are marked =Partial=).

Deliberately *out of scope*: remote/cloud sync, assignees and comments are =org-trello='s domain via the Trello service and run counter to Simply Kanban's offline, single-file model — listed for completeness, not as planned work.

* Development

There is an ERT suite and a =Makefile=:

#+begin_src bash
make test       # run the ERT suite
make compile    # byte-compile, treating warnings as errors
make checkdoc   # run checkdoc
make lint       # run package-lint (after `make deps')
make deps       # install package-lint into ./.elpa
make all        # compile + test + checkdoc
#+end_src

A GitHub Actions workflow (=.github/workflows/ci.yml=) runs these across Emacs 27.2–30.1 and snapshot on every push and pull request.
